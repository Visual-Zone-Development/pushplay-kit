# Online multiplayer and party games

For a JavaScript game built on the runtime files. `pushplay` is the command the `pushplay-rules` skill gives you. Both kinds talk to the shared relay, and to nothing else.

## Online multiplayer (`net.js`, `lobby.js`)

- `pushplay new-game <id> --online --players <min>-<max>` adds `net.js` (connection, rooms, synced state) and `lobby.js` (Quick match / Host / Join, no text entry). Both are runtime files: import them, never edit them. Details and the full API: [multiplayer.md](../../pushplay-runtime/references/multiplayer.md). To add them to an existing game by hand, the templates are in `$(pushplay where)/templates/online/`.
- **The host runs the game.** Every copy calls `net.setInput({...})` each frame and draws `net.view`; only the host runs the rules in `hostUpdate(dt)`, reading `net.inputs[id]` and writing `net.state`. `net.js` sends only what changed. Put only what players must see in `net.state`; particles and shake come from `net.event`.
- **Flow:** `title` → `lobby` (`lobby.update()` returns `'start'` or `'back'`) → `playing` ↔ `paused`. Keep it, and keep `state.screen` and `window.__game`: the check plays two copies together through a local relay and still presses `menu` expecting `'paused'`.
- **Pause can't freeze a shared world.** `menu` (Start / Esc / P / on-screen button) still opens a `menu.js` pause menu (Resume, Settings, Leave game), but it only stops your own controls (`net.setInput({})`) while the host keeps running. `'back'` resumes; Leave game calls `net.leave()` and returns to the lobby. Everything in [menus-and-exit.md](menus-and-exit.md) still applies: the launcher owns quitting.
- Show who's who ("You", colours by `net.slot(id)`). Tag it `"online multiplayer"`, set `players` to e.g. `"2-4"` and `"online": true` (the scaffold does). Bump `version` when the netcode changes: only builds with the same version play together.
- **Dropped connections:** phones suspend the socket when the app is hidden; `net.js` reconnects to the same room and seat and resumes in place. `net.status` gains `'reconnecting'` next to its usual values, and `net.connection` is `'connected' | 'reconnecting' | 'offline'`: show "Reconnecting…" over play and on the pause screen while `net.status === 'reconnecting'`, and "Connection lost" with a way back to the lobby when `net.connection === 'offline'`. `net.away` lists players who dropped and `away` / `back` / `reconnected` events fire.
- **Secrets (a hand of cards, a hidden role):** `net.state` reaches every player, so never put them there. The host writes `net.privateView(id).hand = [...]`; only that player gets it, as `net.mine.hand`.
- `pushplay dev` starts a local relay too, so open two windows to play against yourself.

## Party games (TV + phones: `party.js`, `party-lobby.js`, shared layouts or `controller.html`)

A party game runs on the handheld or PC plugged into a TV. Players join from their phones (scan the QR code, or type the room code at the address on screen) or from any browser, and controllers plugged into the machine can join too. Think Jackbox: a quiz, drawing or bluffing game, a card game with hidden hands, or an action game with phones as gamepads. Full guide: [party.md](../../pushplay-runtime/references/party.md).

- `pushplay new-game <id> --party [--controller <layout>|custom] [--players 3-8]` (up to 16 players). Phones show one of the kit's **shared layouts**: `classic` (default: stick and A B X Y), `pad` (stick, A, B), `twin`, `dpad`, `tap`, `swipe`, `slider`, `trackpad`, `choices` or `motion` (which adds `motion.js` to read tilt, steering and swings on the TV; see [motion.md](../../pushplay-runtime/references/motion.md): phones can't point at the screen). `custom` starts a phone screen of the game's own (`controller.html`) instead. **Prefer a shared layout**: it's tested, kept up to date by the kit and already cached on players' phones. `pushplay controllers` shows them all and what each sends; the full reference is [controllers.md](../../pushplay-runtime/references/controllers.md). The runtime files (`party.js`, `party-lobby.js`, `qr.js`, `controller.js`, `controller-layouts.js`, `phone-menus.js`, `net.js`, `motion.js`) are never edited; `controller.html` and `game.js` are yours.
- **The layout is set from the TV,** for everyone or one player, and can change any time: `party.controls('twin')`, `party.controls({ layout: 'choices', prompt, choices }, id)`, with `labels`, `hide`, `pause: false` and `theme` (requirements in the build guide's *Party games*).
- **Every TV menu works from the phones** (pause with Settings and Quit to library, settings, results): nobody should have to touch the TV or the hosting tablet. `phone-menus.js` publishes the open menu and `controller.js` shows it as buttons (party.md, *Screens and flow*).
- **Motion games show a safety screen before the first motion** of a party (give yourself room, hold on tight, a controlled motion), on the TV and as a card on every phone, and wait for each phone's I'm ready (or the TV skips after a couple of seconds). `motion.safety` and `drawSafety()` in the motion scaffold (motion.md, *Safety first*).
- **The TV runs everything.** Each frame, after `input.update(dt)`, call `party.update()`; then read `party.players` (`{ id, name, color, kind: 'phone' | 'local', connected }`) and each player through `party.pad(id)` (`x`, `y`, `aimX`, `aimY`, `value`, `pointer`, `held(b)`, `pressed(b)`, `released(b)`: the same from a phone on a layout and a local controller). Pause when any player's `pad.pressed('menu')` (the layouts' pause button). `party.inputs[id]` is what a custom `controller.html` sent, as sent.
- **Who sees what.** `party.public` goes to every phone (prompt, choices, whose turn); `party.view(id)` goes only to that player's phone (their hand, secret role, private score); everything else stays on the TV. **Secrets never go in `party.public`.** Both are sent as changes only: write them freely.
- **Phone → TV:** the phone screen calls `controller.send(data)` (→ `party.on('msg', ({ from, data }) => …)`) for choices and text, `controller.input({...})` for held controls.
- **A custom `controller.html` is one file** with its HTML, CSS and JS inline (images as `data:` URLs): the TV sends it to each phone, where it runs with no network. It reads `controller.public`, `controller.mine`, `controller.players`, `controller.me` and re-renders on `controller.on('update', fn)`. Design it for a phone held in one hand: big tap targets, portrait for custom screens. The runtime's lobby screen covers the phones until the game starts. The `party-phone-screen` skill builds it.
- **Flow:** `title` → `lobby` (`lobby.update()` returns `'start'` or `'back'`; the first phone, A on the TV, or a tap or click on the lobby's on-screen Start starts; its on-screen Back leaves, so a touch-only tablet host isn't stuck) → `playing` ↔ `paused`. Unlike online games, **pause freezes the world**: the TV runs it. Set `party.public.paused` so phones can show it, and draw `drawJoinBadge()` during play so latecomers can join (or `party.lock()` to stop them).
- Phones that drop (screen lock, Wi-Fi) keep their seat for two minutes and come back with everything; their `party.inputs` go empty meanwhile, so nothing runs away. Show away players dimmed (`connected: false`).
- Latency is about 50–150 ms from phone to TV: great for party, quiz, card and brawler games, not for precise aiming. Tag it `"party"` (the scaffold sets `"party": true` and the tags).
- `pushplay dev`: phones on the same Wi-Fi scan the lobby's QR code. A party game runs on the TV, so it isn't a phone game: `--party` and `--phone` don't go together.

## Phones as controllers in any game (`phone-pads.js`)

A game that isn't a party game can take phones as controllers too, single-player included (the build guide's *Phones as controllers*). `pushplay new-game <id> --phones` wires it up; an existing JavaScript game adds `import { connectPhones } from './phone-pads.js'` and runs `pushplay update-runtime`, which adds the files.

- `const phones = connectPhones(input, { layout: 'pad', labels: { a: 'Jump' } })` once. Each phone that joins is a pad in `input.pads`, so `input.x`, `input.held('a')` and `input.pressed('menu')` include it with no other change; `input.onPause` fires when one drops.
- A "Connect a phone" screen from the title and pause menus (`phones.menuItem`) draws `phones.drawCard(ctx, x, y)`: QR code, address, room code and who's in. The room opens the first time the card is drawn.
- `phones.controls(settings)` changes the layout, as `party.controls` does. Not with `--party` (it has phones already) or `--online`.
